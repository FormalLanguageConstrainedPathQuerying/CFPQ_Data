# Detailed Plan: Task 150 — Graph registry + metadata API (per-graph registry.json)

Part of hub #148 (end-user core rework). Closes #147 (expose the dataset
category of each graph). Design: `docs/flpq.rst` "Core API: metadata, lazy
access, and cache" (task #149) + the global plan comment on hub #148.

## Context

Metadata today is scattered: the `GRAPHS` name list (`data.py`),
`reachable_pairs.csv` (category + grammars per graph×grammar), docs RST
tables (nodes/edges/size), archive READMEs. This task adds the machine-
readable per-graph registry and the network-free metadata API. The registry
is generated by a repo-only maintenance script from the live archives
(sha256, MTX dims, queries tree) + the CSV (category); it is bundled in the
wheel for the current dataset version.

**Spec:**
- `flpq_data/config.py`: add `DATASET_VERSION = f"{VERSION[0]}.0.0"` to
  `__all__` and the module body — the dataset version served on object
  storage, now a single source of truth (the expression is currently
  duplicated in `data.py:23` and `reachable_pairs.py:26`).
- `data.py`: `DATASET_KEY_PREFIX = f"{DATASET_VERSION}/graph"`;
  `reachable_pairs.py`: `REACHABLE_PAIRS_KEY_PREFIX = DATASET_VERSION`.
  Values are unchanged (`6.0.0/graph`, `6.0.0`); existing URL tests keep
  passing.
- `utils/generate_registry.py` (pattern of `utils/archive_sizes.py`;
  imports sibling utils modules directly, like `merge_archive.py` does):
  - `_sha256(path) -> str` — streaming sha256 (hashlib).
  - `archive_record(graph_dir: Path) -> dict` — pure function over an
    unpacked archive dir: `num_nodes`/`num_edges` from
    `flpq_data.graphs.readwrite.mtx.graph_from_mtx_dir(graph_dir/"graph")`
    (`number_of_nodes()`/`number_of_edges()`); `queries` by walking
    `queries/<class>/<query>/` with `QUERY_CLASSES` from
    `check_archive_structure` — one entry per query dir: `{"class": <class>,
    "name": <dir name>, "representations": sorted extensions without dots}`;
    queries sorted by (class, name).
  - `build_record(name, url, workdir) -> dict` — download the archive to a
    temp file (`requests.get(stream=True)` + `raise_for_status`), compute
    sha256 and the byte size while streaming, unpack into `workdir`, run
    `archive_record`; returns `num_nodes`, `num_edges`,
    `size_mb = round(size / 1_000_000, 3)`, `sha256`, `queries`.
  - `build_registry(workdir) -> dict` — graph list + category from
    `load_rows(MAIN_FOLDER / "flpq_data/dataset/reachable_pairs.csv")`
    (reused from `reachable_pairs_tables`); assert one category per graph;
    fetch every record concurrently (`ThreadPoolExecutor`, 8 workers, like
    `fetch_sizes`); all-or-nothing — collect failures and raise
    `RuntimeError` listing them. Result: `{"version": DATASET_VERSION,
    "graphs": {<name>: {"category", "num_nodes", "num_edges", "size_mb",
    "sha256", "queries"}}}` with graph names in sorted order.
  - `write_registry(registry, path)` — `json.dumps(..., indent=2)` +
    trailing newline; deterministic byte-for-byte for equal registries.
  - `main()` — no flags; builds the registry and writes
    `flpq_data/dataset/registry.json`; prints a summary (graph count, total
    size). Local-only: never runs in CI (no-network policy).
- numpydoc docstrings with `Examples` on the pure functions (same style as
  `archive_sizes.py`).

### S3: flpq_data/dataset/registry.py — the metadata API [done] (5c7e98b)

**Code:** New `flpq_data/dataset/registry.py` (`QueryInfo`, `GraphInfo`,
`graphs`, `graph_info`, `categories`); export via
`flpq_data/dataset/__init__.py`
**Tests:** New `tests/dataset/test_registry.py` against the real bundled
`registry.json`
**Docs:** `docs/reference/dataset/index.rst` autosummary (add the five new
names), numpydoc docstrings with doctest `Examples`, CHANGELOG `[Unreleased]`
Added entry

**Spec:**
- `QueryInfo` frozen dataclass: `query_class: str`, `name: str`,
  `representations: tuple[str, ...]`.
- `GraphInfo` frozen dataclass: `name: str`, `category: str`,
  `num_nodes: int`, `num_edges: int`, `size_mb: float`, `sha256: str`,
  `queries: tuple[QueryInfo, ...]`.
- `_load_registry() -> dict` — reads the bundled
  `pathlib.Path(__file__).parent / "registry.json"` once and caches it at
  module level. The metadata path never touches the network.
- `graph_names() -> list[str]` — sorted graph names (named to avoid
  clashing with the `flpq_data.graphs` subpackage, which would shadow a
  top-level `graphs` name through the star-import chain).
- `graph_info(name: str) -> GraphInfo` — the record for `name`; raises
  `FileNotFoundError(f"No graph with {name=} found")` for unknown names
  (same message style as `download_graph`). Maps the JSON `"class"` key to
  the `query_class` field explicitly.
- `categories() -> dict[str, list[str]]` — category -> sorted graph names,
  categories in sorted order (the #147 mapping).
- `__all__ = ["GraphInfo", "QueryInfo", "graphs", "graph_info",
  "categories"]`; add `from .registry import *` to `dataset/__init__.py`.
- Doctest examples use the real bundled data with stable output (e.g.
  `len(graph_names())` -> 113, `graph_info("skos").category` -> 'rdf').
- Tests: `len(graph_names()) == 113` and sorted; graph set equals the CSV's graph
  column; `graph_info("skos")` fields (rdf, 144, 252); a record with an RPQ
  or MCFPQ query if present, else CFPQ-only; unknown name raises
  `FileNotFoundError`; `categories()` agrees with the CSV category column
  for every graph and covers all 113 graphs; `GraphInfo`/`QueryInfo` are
  frozen (dataclasses.FrozenInstanceError on setattr).
- CHANGELOG Added entry: the per-graph `registry.json` (bundled + published
  as `<version>/registry.json`), its fields, `utils/generate_registry.py`,
  and the network-free API `graphs()`/`graph_info()`/`categories()` (#147).
